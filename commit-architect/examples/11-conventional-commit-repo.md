# Example 11: Conventional Commit Repository (Explicit Rule Precedence)

This example demonstrates how Commit Architect detects when a repository mandates Conventional Commits and adapts its message formatting accordingly, overriding the natural language default.

---

## 1. The Task
"Implement an API endpoint to delete an inactive user account."

## 2. Repository State & Discovery
* Running repository inspection reveals:
  * `.commitlintrc.json` configured with `@commitlint/config-conventional`.
  * `package.json` contains a `commit-msg` Husky hook running `commitlint -E HUSKY_GIT_PARAMS`.
  * `git log -n 5 --oneline` shows:
    ```text
    c3d4e5f feat(users): add user profile update endpoint
    a1b2c3d fix(auth): prevent session timeout during active uploads
    f5g6h7i chore(deps): bump typescript from 5.3 to 5.4
    ```
* **Decision:** The repository explicitly requires Conventional Commits. The agent must adhere to Conventional Commits format with appropriate types and scopes.

## 3. Discovered Work
1. Add `DELETE /api/v1/users/:id` route in `routes/users.ts`.
2. Add `deleteUser` method in `services/userService.ts` (marks user as soft-deleted).
3. Add route authorization check ensuring only admins or the user themselves can delete their account.
4. Add integration tests in `tests/routes/users.delete.test.ts`.

## 4. Proposed Commit Plan
* **Single Cohesive Commit:**
  `feat(users): add account deletion endpoint with soft-delete support`

## 5. Implementation Sequence
1. Implement service method and route handler with authorization check.
2. Add integration tests. Run `npm test`. Verify green.
3. Validate commit message with Commit Architect verifier in `--conventional` mode:
   ```bash
   python scripts/verify-commit.py --conventional -m "feat(users): add account deletion endpoint with soft-delete support"
   ```
4. Commit.

## 6. Final Commit Message
```text
feat(users): add account deletion endpoint with soft-delete support

Add DELETE /api/v1/users/:id endpoint allowing users to delete their own
account and administrators to delete any account. Flags database record as
deleted_at timestamp rather than hard deleting related order records.
```

## 7. Why This Message Format is Used
* **Repository Precedence:** Explicit project standards and automated git hooks always take precedence over the skill's default natural language style.
* **Clean Conventional Syntax:** Follows standard type (`feat`), established project scope (`users`), imperative description, and an informative body. Avoids artificial over-specification like `feat(controllers-api-v1-users-delete): ...`.

## 8. What the Agent Should Avoid
* ❌ Refusing to follow Conventional Commits when the repository's CI / commitlint will reject natural messages.
* ❌ Using invalid types (e.g., `feature:`, `bugfix:`, `task:` when the project uses standard types).
* ❌ Adding AI attribution footers: `feat(users): add delete endpoint (generated by AI)`.
