## Git Commit Architecture Guidelines
When preparing, staging, or committing Git changes:
1. Divide work by logical intent, balancing atomicity and cohesion.
2. Avoid monolithic commits bundling backend, frontend, database, and documentation changes.
3. Avoid micro-commits for isolated variable renames or formatting edits.
4. Always inspect working tree (`git status --porcelain`) and staged diff (`git diff --cached`) before committing. Never execute `git add .` blindly.
5. Default to natural, concise, imperative developer commit messages (e.g. `Add Google login support`).
6. Do NOT automatically use Conventional Commit prefixes (`feat:`, `chore:`, etc.) unless explicitly specified by repository rules or commitlint.
7. Do not include unsolicited AI attribution footers (`Generated by AI`, `Co-authored-by: AI`).
